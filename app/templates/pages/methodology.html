1. Data

The preferred dataset is the CC0-licensed Flood Risk in India dataset from Kaggle, containing meteorological, hydrological and socio-economic features across India with a binary Flood_Occurred label. When the real dataset is unavailable, the pipeline generates a clearly-labelled synthetic dataset with matching schema for demonstration.

2. Cleaning

  • Column-name normalization and type coercion.
  • Duplicate row removal.
  • Physically plausible clipping of numeric outliers (e.g., rainfall 0–2000 mm).
  • Median / mode imputation for missing values.
  • Canonicalization of categorical labels (e.g., urban → Urban).

3. Feature Engineering

  • Rainfall_72h_proxy: sqrt-transformed rainfall as a proxy for antecedent wetness.
  • Rainfall_x_Level: interaction between rainfall and water level.
  • Discharge_x_Humidity: interaction between river flow and humidity.
  • Elevation_inv: 1/(elevation+10) capturing flood-proneness of low-lying areas.
  • Ordinal 4-class risk target derived from a weighted risk score (see below).

4. Target Definition

The original dataset ships only with a binary flood label. We construct a continuous Risk Score (0–1) as a weighted combination of percentiles of rainfall, water level, river discharge, humidity, inverse elevation plus penalties for soil drainage, land cover, historical floods, and a mitigation term for infrastructure. The score is binned into four classes (Low / Moderate / High / Critical), and every observed flood event is promoted to at least High. See src/feature_engineering.py for the exact formula.

5. Modelling

The preprocessing pipeline (median imputation + standard scaling for numerics, one-hot encoding for categorics) is wrapped inside a scikit-learn Pipeline together with the classifier to prevent data leakage. We benchmark Logistic Regression, Decision Tree, Random Forest, Gradient Boosting and optionally XGBoost, selecting the best by macro-F1 with recall as a tie-breaker. The best model is lightly tuned with RandomizedSearchCV (3-fold stratified CV) and serialized with joblib.

6. Explainability

To stay lightweight for deployment we use a transparent contribution method: numeric features are measured in z-scores from the training mean, weighted by their direction of influence (e.g., high elevation reduces risk); categorical features contribute by their average risk relative to the global mean. Results are presented in plain English and labelled as influencing the model's prediction — not as causal statements.

7. Serving

Flask loads the serialized pipeline once at startup and exposes both an HTML interface and a JSON API (/api/predict, /api/health, /api/metadata). Predictions are logged to a local SQLite database for the history page.

Why these choices?

  • Scikit-learn pipelines avoid leakage and make deployment simple.
  • Macro-F1 / recall over raw accuracy because classes can be imbalanced and missing a high-risk event is worse than a false alarm.
  • Tree ensembles (RF / GB / XGB) handle non-linear relationships and mixed feature types well.
  • Lightweight explanation keeps deployment simple on free tiers, where SHAP's dependency weight can be problematic.
